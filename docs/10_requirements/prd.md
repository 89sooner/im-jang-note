# 임장노트 PRD

## 1. 문서 개요

- 문서명: 임장노트(ImJang Note) 제품 요구사항 문서
- 문서 버전: v0.1
- 작성일: 2026-05-29
- 대상 독자: Product, Design, Engineering, QA, Security, Operations
- 상위 기준 문서: `srs_final.md`(최종 범위 기준). 본 PRD가 `srs_final.md`와 충돌하면 SRS를 우선한다.
- 한 줄 정의: **부부가 함께 부동산 임장(현장 방문) 기록을 지도 기반으로 작성·공유·비교하는 모바일 앱.**

## 2. 배경과 문제 정의

- 내 집 마련·이사·투자를 위해 여러 단지를 직접 방문(임장)하면, 단지별 인상·장단점·시세 감각이 빠르게 휘발된다.
- 부부가 따로 메모(사진첩, 카톡, 메모앱)하면 기록이 흩어지고, 같은 단지를 서로 다르게 기억해 의사결정이 어렵다.
- 기존 부동산 앱은 매물 거래·중개 중심이라 "현장에서 우리 부부의 주관적 평가를 구조화해 남기고 함께 비교"하는 흐름이 없다.
- 임장 현장은 지하·신축 등 전파가 약한 경우가 많아 오프라인 기록과 사후 동기화가 필요하다.

## 3. 제품 목표

### 3.1 제품 목표

1. 지도에서 단지를 누르면 즉시 임장 후기를 구조화해 기록할 수 있게 한다.
2. 부부 2인이 하나의 공유 공간에서 실시간으로 기록을 보고, 코멘트로 합의에 이르게 한다.
3. 국토부 실거래가·단지 정보를 옆에 붙여 주관적 평가와 객관적 시세를 함께 본다.
4. 후보 단지를 비교표로 정리해 "어디로 갈지" 결정을 돕는다.
5. SaaS 수준의 인증·권한·실시간·관측·개인정보 보호를 갖춰 신뢰할 수 있게 한다.

### 3.2 비목표 (Non-goals)

- 매물 거래·중개·계약 기능을 제공하지 않는다.
- 공개 커뮤니티/소셜 피드를 제공하지 않는다.
- 3인 이상 협업, 부동산 추천 알고리즘은 초기 범위가 아니다.

## 4. 대상 사용자 / 페르소나

| 사용자 유형 | 페르소나 | 목표 | 주요 작업 | 권한/제약 |
| --- | --- | --- | --- | --- |

## 6. 범위

### 6.1 In Scope (P0)

- 인증/계정 (F-AUTH-001~003), 부부 워크스페이스 생성·초대·실시간 동기화 (F-WS-001~003)
- 지도 기반 단지 탐색·마커 클릭 진입·현위치 (F-MAP-001~004)
- 단지 기본정보·실거래가 조회 및 캐시 (F-DATA-001~003)
- 임장 노트 작성/목록/수정·삭제, 구조화 체크리스트, 별점, 자유 메모 (F-NOTE-001~006)
- 사진 첨부 (F-MEDIA-001)
- 노트 코멘트 (F-COMMENT-001)
- 즐겨찾기/후보 등록 (F-FAV-001)
- 지역/단지명 검색 (F-SEARCH-001)
- 위치/개인정보 동의 관리 (F-SET-002)

### 6.2 Conditional Scope (P1, 용량·일정 여유 시)

- 멤버 권한/역할 (F-WS-004), 노트 보유 단지 시각 구분 (F-MAP-005), 평형별 시세 필터 (F-DATA-004)
- 사진 뷰어 (F-MEDIA-002), 단지 비교 (F-FAV-002), 조건 필터 (F-SEARCH-002)
- 알림(F-NOTIFY-001~002), 오프라인 작성·동기화 (F-SYNC-001~002), 설정 (F-SET-001), 계정 탈퇴 (F-AUTH-004)

### 6.3 Out of Scope

- 매물 거래/중개 (F-OUT-001), 공개 커뮤니티 (F-OUT-002), 3인+ 협업 (F-OUT-003), 결제/구독 (F-OUT-004), AI 추천 (F-OUT-005)
- 노트 변경 이력(F-NOTE-007), 사진 EXIF 위치(F-MEDIA-003), 데이터 export(F-SET-003)는 P2 보류.

## 7. 핵심 사용자 시나리오

### SCN-001 주말 임장 현장 기록 (P0)

- 시작 조건: 로그인된 owner가 단지 앞에 있음, 위치 권한 허용.
- 기본 흐름: 지도 홈(D-002) → 현위치 이동 → 단지 마커 클릭 → 단지 상세(D-003) → "임장 노트 작성"(D-004) → 별점·체크리스트·사진·메모 입력 → 저장 → 워크스페이스 실시간 반영.
- 대체 흐름: 미등록 단지 → 좌표 기반 신규 단지 생성 후 노트 작성.
- 오류 흐름: 네트워크 약함 → 로컬 큐 저장(F-SYNC-001) 후 온라인 복귀 시 동기화.
- 관련 요구사항: FR-MAP-001~004, FR-NOTE-001~004, FR-MEDIA-001, FR-SYNC-001.

### SCN-002 배우자와 후보 비교 (P1)

- 시작 조건: 워크스페이스에 2인 연결, 후보 단지 3곳 노트 존재.
- 기본 흐름: 즐겨찾기(D-008) → 비교(D-006) → 평점·시세·체크리스트 비교표 확인 → 노트 상세(D-012)에서 코멘트로 의견 합의.
- 관련 요구사항: FR-FAV-001~002, FR-DATA-002, FR-COMMENT-001.

### SCN-003 오프라인 지하 현장 (P1)

- 시작 조건: 전파 약한 신축 지하 견본.
- 기본 흐름: 오프라인 표시 확인 → 노트 작성·사진 첨부 → 로컬 저장 → 지상 이동/온라인 복귀 → 자동 동기화·충돌 없음 확인.
- 오류 흐름: 동시 편집 충돌 → 정책(기본 last-write-wins + 충돌 알림, ADR-005)으로 해소.
- 관련 요구사항: FR-SYNC-001~002, FR-MEDIA-001.

### SCN-004 실거래가 확인 후 평가 (P0)

- 기본 흐름: 단지 상세(D-003) → 국토부 실거래가 추이 확인 → 시세 인지 후 노트 평가 보정.
- 오류 흐름: 국토부 API 장애 → 캐시 폴백 + "최신 아님" 배지(저하 모드).
- 관련 요구사항: FR-DATA-001~003, NFR-004.

### SCN-005 초대로 워크스페이스 합류 (P0)

- 기본 흐름: owner가 초대 링크 공유 → partner 앱 설치/로그인 → 초대 수락 → 기존 노트 즉시 열람.
- 오류 흐름: 만료/사용된 코드 → 재발급 요청.
- 관련 요구사항: FR-WS-002~004, FR-AUTH-001.

## 9. 비기능 요구사항 요약

- 성능(NFR-001): 지도 첫 렌더 2.5초 이내(LTE), 마커 1,000개까지 60fps 근접 스크롤, 노트 저장 1초 이내(온라인).
- 보안(NFR-002): Supabase Auth + Row Level Security로 워크스페이스 단위 격리. 국토부/지도 API 키는 클라이언트 비노출(Edge Function 프록시).
- 개인정보(NFR-003): 위치·사진은 명시 동의 후 수집, 동의 철회·삭제 가능. 개인정보보호법(PIPA) 고지 준수.
- 가용성/신뢰성(NFR-004): 외부 API 장애 시 캐시 폴백 + 저하 모드 표시. 오프라인 작성 무손실.
- 접근성(NFR-005): 한 손 조작·큰 터치 타깃, 스크린리더 레이블, 명도 대비 WCAG AA.
- 운영/관측(NFR-006): 구조화 로그·메트릭·트레이스, 크래시 리포팅, 핵심 흐름 알림 룰.
- 확장성/이식성(NFR-007): RN/Expo로 Android 우선, iOS 확장 여지. 지도/데이터 공급자 교체 가능하도록 어댑터 경계 유지.

## 10. 아키텍처 및 실행 환경 가정

- 클라이언트: React Native + Expo (Android 우선). 서버상태 React Query, 클라이언트상태 Zustand, 알림 Expo Notifications.
- 지도: Kakao Map. RN 연동 방식은 ADR-003에서 확정(네이티브 SDK 래퍼 vs WebView 브리지).
- 데이터: 국토교통부 공공데이터 OpenAPI(공동주택 단지 정보 + 아파트 실거래가). 클라이언트 직접 호출 금지, Supabase Edge Function 프록시·캐시 경유(ADR-004).
- 백엔드: Supabase (Postgres + Auth + RLS + Realtime + Storage + Edge Functions).
- 테넌시: 워크스페이스(=부부 그룹) 단위 데이터 격리, RLS 기본 적용.

## 11. 릴리스 전략

- P0 (REL-001~003): 로그인·워크스페이스 → 지도·단지데이터 → 노트작성·사진. "현장에서 단지 클릭→기록" 핵심 흐름 완성.
- P1 (REL-004~005): 공유·실시간·코멘트 → 검색·비교·즐겨찾기·알림. 부부 협업·의사결정 강화.
- P2 (REL-006): 오프라인·동기화 하드닝, 관측·접근성·성능 마감. SaaS 품질 완성.

## 13. 리스크 및 가정

- 국토부 OpenAPI 쿼터/지연/데이터 누락 → 캐시·저하 모드로 완화(FR-DATA-003, NFR-004).
- Kakao Map RN 연동 난이도 → 초기 스파이크로 ADR-003 조기 확정.
- 부부 2인 동시 편집 빈도는 낮다고 가정하나 충돌 정책은 명시(ADR-005).
- 위치/사진 등 민감정보 취급 → 동의·삭제 흐름을 P0에 포함(F-SET-002).
