# 임장노트 관측성 및 신뢰성

## 1. 목적과 범위

이 문서는 임장노트의 SLO/SLI, 로그·메트릭·트레이스, 크래시 리포팅, 알림 룰, 대시보드, 런북, 저하 모드(degraded mode), 용량/장애 모드를 정의한다. 성능/신뢰성 목표는 NFR-001(성능), NFR-004(신뢰성)에 근거하고 관측성 요구는 NFR-006이다. 상위 구조는 `imjang_note_system_architecture.md`, 인프라 절차는 `imjang_note_infrastructure_operations.md`, 위협/감사 연계는 `imjang_note_security_privacy_architecture.md`를 따른다. 새 제품 범위를 추가하지 않는다.

## 2. SLO / SLI

성능 목표는 SRS §12 / 시스템 문서 §6의 NFR-001 수치를 기준으로 한다.

| SLO ID | SLO | SLI | 목표 | 측정 위치 | 관련 요구사항 |
| --- | --- | --- | --- | --- | --- |
| SLO-01 | 지도 첫 렌더 지연 | LTE 환경 지도 첫 렌더 시간 p90 | 2.5s 이내 | 앱 성능 이벤트 | NFR-001, FR-MAP-001 |
| SLO-02 | 노트 저장 응답 | 노트 저장 write p90 | 1s 이내 | 앱+RPC 지연 | NFR-001, FR-NOTE-001 |
| SLO-03 | 실거래 표시(캐시 적중) | 캐시 적중 시 표시 지연 p90 | 1.5s 이내 | Edge Fn + 앱 | NFR-001, FR-DATA-002 |
| SLO-04 | 가용성 | 핵심 read/write 성공률 | 99.5% | Supabase/Edge 로그 | NFR-004 |
| SLO-05 | 외부 데이터 신뢰성 | 국토부 프록시 성공률(폴백 제외) | 95% 이상, 실패 시 stale 폴백 | Edge Fn 로그 | NFR-004, FR-DATA-003 |
| SLO-06 | 동기화 무손실 | 오프라인 큐 재생 성공률 | 99.9% | 앱+RPC | NFR-004, FR-SYNC-001/002 |
| SLO-07 | 푸시 전달 | 알림 발송 성공률 | 95% 이상 | JOB-NOTIFY-001 로그 | NFR-004, FR-NOTIFY-001 |
| SLO-08 | 크래시 프리 | 크래시 없는 세션 비율 | 99.5% | 크래시 리포팅 | NFR-004, NFR-006 |

오류 예산: SLO-04 99.5%는 월 단위 오류 예산으로 관리하며 소진 시 신규 배포 동결·하드닝 우선(REL-006).

## 3. Telemetry

- request logs: Edge Function/PostgREST 요청 로그(요청 id, 경로, 상태, 지연, 워크스페이스 스코프). 시크릿·위치·토큰 마스킹(보안 문서 §9).
- audit logs: 중요 write/동의/삭제 감사(보안 문서 §6) — 운영·오남용 탐지에 활용.
- job logs: JOB-DATA-001/002, JOB-NOTIFY-001, JOB-MEDIA-001의 시작/종료/건수/실패/재시도/적체.
- frontend events: 화면 진입, 지도 렌더 시간, 노트 저장 지연, 동기화 큐 길이·재생 결과, 동의 변경(NFR-006).
- traces: 앱 → Edge Function → 외부 API 구간 상관(request_id 전파)으로 외부 의존 지연 분리.
- business metrics: 외부 API 호출량/쿼터, 캐시 적중률, 신선도 만료율, 활성 워크스페이스/디바이스 토큰.

## 4. Alerts

| Alert ID | 조건 | Severity | Runbook |
| --- | --- | --- | --- |
| ALT-01 | 국토부 프록시 실패율 > 20% (5분) | High | RB-01 국토부 장애 |
| ALT-02 | 캐시 적중률 급락 / 신선도 만료율 급증 | Medium | RB-01 국토부 장애 |
| ALT-03 | 동기화 큐 재생 실패율 > 1% 또는 적체 지속 | High | RB-02 동기화 적체 |
| ALT-04 | 푸시 발송 실패율 > 10% (JOB-NOTIFY-001) | Medium | RB-03 푸시 실패 |
| ALT-05 | 핵심 read/write 성공률 < 99.5% (SLO-04 위반) | Critical | RB-04 가용성 저하 |
| ALT-06 | 마이그레이션 실패/롤백 트리거 | Critical | RB-05 마이그레이션 실패 |
| ALT-07 | 크래시 프리 세션 < 99.5% (SLO-08) | High | RB-06 크래시 급증 |
| ALT-08 | 교차 워크스페이스 접근 시도/RLS deny 급증 | Critical | RB-07 권한 이상 |
| ALT-09 | 외부 API 사용량/쿼터 임계 근접 | Medium | RB-01 국토부 장애 |
| ALT-10 | 삭제 Job 미완료/적체 (PIPA) | High | RB-08 삭제 미완료 |

알림은 actionable(임계·기간·런북 링크 포함)하게 정의하며, 정보성 노이즈는 대시보드로만 노출한다.

## 5. Runbooks

- RB-01 국토부 장애: 프록시 실패율/쿼터 확인 → stale 캐시 폴백 동작 확인 → 앱 저하 모드 배너(신선도 표시) 확인 → 백오프/배치 재시도(JOB-DATA-001/002) → 장기화 시 갱신 주기 조정. 영향: 실거래·단지 메타 신선도 저하만, 노트 작성·열람은 정상.
- RB-02 동기화 적체: 큐 길이/재생 실패 원인(충돌/RPC 오류/네트워크) 분류 → idempotency key 기반 재생 재시도 → 충돌은 ADR-005 정책으로 처리 → 지속 실패는 DLQ성 상태로 격리 후 점검. 무손실 보장(SLO-06).
- RB-03 푸시 실패: Expo Push 응답 코드 확인 → 만료/무효 device_token 정리(ENT-DEV-001) → 재시도, 동의 철회 토큰 제외 확인.
- RB-04 가용성 저하: Supabase 상태/지연 확인 → 저하 모드(캐시 read, 오프라인 큐)로 핵심 열람 유지 → 원인(쿼리/커넥션/함수) 격리 → 필요 시 인스턴스 등급 상향 또는 롤백.
- RB-05 마이그레이션 실패: 적용 중단 → down 마이그레이션 또는 PITR 복원(인프라 §7) → 하위호환 재설계 → 재적용.
- RB-06 크래시 급증: 크래시 리포트 스택/버전 식별 → 영향 버전 OTA 롤백(EAS Update) → 핫픽스.
- RB-07 권한 이상: RLS deny/교차접근 로그 분석 → 정책 회귀 여부 확인 → 영향 시 즉시 정책 롤백 + 노출 평가(보안 문서 §9, THR-001).
- RB-08 삭제 미완료: 삭제 Job 실패 원인 확인 → 멱등 재실행 → Storage 객체·서명 URL 무효화 확인 → 완료 감사(보안 문서 §7, THR-008).

## 6. 크래시 리포팅

- 앱 크래시/JS 예외를 리포팅 도구로 수집(버전/디바이스/스택). 위치·사진·토큰 등 민감필드는 스크러빙(보안 문서 §9).
- 크래시 프리 세션(SLO-08)을 릴리스 게이트 지표로 사용(검증 문서 §3), 회귀 시 OTA 롤백(RB-06).

## 7. 저하 모드 (Degraded Mode)

- 외부 데이터 원천 장애: 캐시 우선 read + stale 폴백 + 신선도/저하 배너 표시(NFR-004, FR-DATA-003).
- 백엔드 가용성 저하: 오프라인 큐로 작성 보류, 캐시된 노트/단지 read 유지, 복구 후 idempotent 재생.
- 푸시 장애: 알림 미발송 시 앱 내 변경(Realtime/재조회)으로 보강.

## 8. 용량 / 장애 모드

- 용량 지표: 동시 Realtime 연결, Edge Function 동시 실행/콜드스타트, Postgres 커넥션·지연, Storage 용량, 외부 API 쿼터(인프라 §8).
- 주요 장애 모드: 외부 API 장애(→저하 모드), 동기화 적체(→RB-02), RLS 회귀(→RB-07), 마이그레이션 실패(→RB-05). 각 모드는 ALT/RB와 1:1 매핑.
