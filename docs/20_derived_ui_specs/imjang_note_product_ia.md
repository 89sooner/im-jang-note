# 임장노트 제품 IA 문서

## 0. 현재 문서 세트와 사용 순서

이 문서는 `docs/20_derived_ui_specs/`의 **최상위 IA 기준 문서**이며 모든 화면 ID(D-001~D-012)의 **단일 정의처**다. 다른 파생 UI 문서(와이어프레임, 플로우, 상태 매트릭스, 컴포넌트, 토큰, QA)는 이 문서가 정의한 화면 ID 체계를 참조만 하고 재정의하지 않는다.

이 문서는 새 제품 범위를 만들지 않는다. `docs/10_requirements/srs_final.md`와 `prd.md`의 승인된 기능요구(FR-*)·비기능요구(NFR-*)를 화면 구조로 번역한다. 요구사항↔화면 매핑은 `docs/10_requirements/requirements_screen_traceability_matrix.md`와 일치해야 한다.

읽는 순서: 본 IA → 와이어프레임 → 플로우 → 상태 매트릭스 → 컴포넌트 → 토큰 → QA.

## 1. 제품 한 줄 정의

부부 2인이 하나의 공유 워크스페이스에서 지도 위 단지를 클릭해 구조화된 임장(현장방문) 후기를 작성·공유·비교하는 모바일 앱.

## 2. 대상 사용자·운영 환경

- 사용자: 함께 주택을 알아보는 부부 2인(워크스페이스 멤버 최대 2명 기준). 역할은 동등(소유자/멤버 구분은 워크스페이스 관리 한정).
- 환경: Android 우선의 모바일 앱(Expo/React Native), iOS 확장 여지. 야외·이동 중·한 손 조작·저조도/고조도 화면, 불안정한 네트워크에서의 현장 작성이 핵심 맥락이다.
- 기술 표면: Kakao Map, 국토교통부 공공데이터(단지정보·실거래가) Edge Function 프록시, Supabase(Auth/Postgres/RLS/Realtime/Storage/Edge Functions), 오프라인 작성 후 동기화.

## 3. IA 설계 원칙

1. **작업 중심 구조**: "지도에서 단지 발견 → 임장 노트 작성 → 공유·비교"라는 핵심 작업 경로(F-001)를 가장 짧게 만든다.
2. **점진적 공개**: 지도 홈(D-002)은 단지 마커 → 단지 상세(D-003) → 노트 작성(D-004) 순으로 정보를 단계적으로 노출한다.
3. **복구 가능성 우선**: 오프라인·동기화중·부분실패 상태를 화면에서 명시적으로 표현하고(C-013), 현장 작성 데이터 유실을 방지한다(FR-SYNC-001/002).
4. **권한/정책의 명시적 노출**: 워크스페이스 RLS 격리, 멤버 초대 권한(FR-WS-*), 개인정보·저하모드(NFR-003, FR-DATA-003)를 화면 상태로 드러낸다.
5. **부부 협업 가시성**: 누가 어떤 노트를 작성/코멘트했는지(C-015 MemberAvatar), 실시간 동기화 결과를 피드(D-005)와 알림(D-010)으로 공유한다.
6. **야외·한 손 조작 최적화**: 주요 액션을 엄지 도달 영역에 두고, 색만으로 상태를 전달하지 않으며 WCAG AA 대비를 유지한다(NFR-005).

## 4. 제품 표면 정의

```text
Product Surface
└─ Primary App (React Native + Expo)
   ├─ 인증/온보딩 표면
   │  └─ D-001 온보딩/로그인
   ├─ 전역 탭 셸 (인증 후 메인)
   │  ├─ [탭1 지도]      D-002 지도 홈
   │  ├─ [탭2 피드]      D-005 노트 목록/워크스페이스 피드
   │  ├─ [탭3 즐겨찾기]  D-008 즐겨찾기/후보 리스트
   │  ├─ [탭4 알림]      D-010 알림 센터
   │  └─ [탭5 설정]      D-011 설정/계정/개인정보
   ├─ 스택/푸시 화면 (탭 위에 push)
   │  ├─ D-003 단지 상세
   │  ├─ D-004 노트 작성/편집
   │  ├─ D-006 단지 비교
   │  ├─ D-007 검색/필터
   │  ├─ D-009 워크스페이스/공유·초대
   │  └─ D-012 노트 상세/코멘트
   └─ 모달/시트 표면
      ├─ D-007 검색/필터 (지도 위 시트 진입 가능)
      └─ 초대 수락(F-002), 알림 딥링크(F-008) 등 컨텍스트 시트
```

이 제품은 관리자 콘솔(A-*) 또는 웹 표면(W-*)을 포함하지 않는다. 모든 표면은 Primary App 내부에 있다.

## 5. 전역 셸과 내비게이션

### 5.1 하단 탭 내비게이션 (인증 후 영구 셸)

| 탭 | 진입 화면 | 역할 | 근거 FR |
| --- | --- | --- | --- |
| 지도 | D-002 지도 홈 | 기본 시작점. 단지 탐색·노트 작성 진입 | FR-MAP-001~005 |
| 피드 | D-005 노트 목록/워크스페이스 피드 | 부부가 작성한 노트 시간순/단지별 공유 | FR-NOTE-005, FR-WS-003 |
| 즐겨찾기 | D-008 즐겨찾기/후보 리스트 | 관심 단지 모음·후보 관리 | FR-FAV-001/002 |
| 알림 | D-010 알림 센터 | 코멘트·초대·동기화 알림 | FR-NOTIFY-001/002 |
| 설정 | D-011 설정/계정/개인정보 | 계정·워크스페이스·개인정보·저하모드 | FR-SET-001/002 |

- 기본 진입 탭은 **지도(D-002)**.
- 탭은 인증된 사용자에게만 노출된다. 비인증 시 D-001로 게이트.
- 워크스페이스(D-009)는 설정 탭(D-011) 또는 알림 딥링크(F-008/F-002)에서 push로 진입한다(독립 탭 아님).

### 5.2 스택·모달 규칙

- 탭 내부에서 단지 상세(D-003)·노트 상세(D-012)·노트 작성(D-004)·비교(D-006)는 push 스택으로 쌓인다.
- 검색/필터(D-007)는 지도 홈의 검색바(C-010)에서 풀스크린 또는 하단 시트로 진입한다.
- 노트 작성(D-004)은 작성 중 이탈 방지를 위해 풀스크린 + 임시저장/동기화 규칙을 따른다(상세는 플로우 문서 F-001/F-003 참조).

### 5.3 전역 요소

- 전역 동기화 상태 배지(C-013 SyncStatusBadge): 오프라인·동기화중·부분실패를 셸 상위에 노출.
- 멤버 아바타(C-015): 협업 컨텍스트(피드/노트/코멘트)에서 작성자 표시.

## 7. 화면 우선순위

핵심 작업 경로(지도→노트 작성→공유)와 협업 신뢰성(동기화)을 우선한다.

- **P0 (핵심 가치, 출시 필수)**: D-001, D-002, D-003, D-004, D-005, D-009. 인증·워크스페이스·지도·단지·노트 작성·피드 공유가 없으면 제품이 성립하지 않는다.
- **P1 (협업·신뢰성 완성)**: D-012(코멘트), D-010(알림), D-008(즐겨찾기), D-007(검색/필터). 부부 협업과 후보 관리 흐름을 완성한다. 오프라인 동기화(FR-SYNC-001/002)는 D-004/D-005에 내장되므로 P0와 함께 검증한다.
- **P2 (의사결정 보조)**: D-006(비교), D-011 고급 항목(저하모드 FR-DATA-003, 관측 동의 NFR-006). 후보 단지 비교와 운영/개인정보 세부 설정을 마무리한다.

우선순위는 범위 변경이 아니라 구현 순서 가이드이며, 모든 화면 ID는 출시 범위에 포함된다.

## 8. 화면 ID 체계 설명

- 형식: `D-###` — Primary App의 주요 모바일 화면. 본 제품은 모바일 단일 표면이므로 `W-###`(웹), `A-###`(관리자)는 사용하지 않는다.
- 번호는 안정적이다. 화면을 제거할 경우 삭제하지 않고 deprecated로 표기하고 사유를 남긴다.
- 컴포넌트는 `C-###`, 플로우는 `F-###`로 별도 네임스페이스를 가지며 본 문서의 화면 ID와 교차 참조된다(컴포넌트 명세·플로우 명세 참조).
- 신규 화면/기능/범위 발명은 금지된다. 본 문서의 D-001~D-012만 유효하다.
